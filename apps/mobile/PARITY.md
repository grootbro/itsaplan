## Delivery sequence

1. Finish and review project board/table/calendar/list, state preservation, canonical
   project references and safe synthetic UI scenarios. Publish to the existing draft PR.
2. Add permission-aware project navigation and cycle/initiative browsing/details with
   task drill-down, shared filters and preserved return state.
3. Complete core task fields, editor/files and permission/error handling against current
   contracts, including large data sets and reliable authenticated attachment handling.
4. Extend accounts, workspace/team switching, invites and notifications.
5. Add compatible server saved views, timeline and the remaining confirmed project
   sections. Track each separately; one finished screen does not complete mobile parity.

Native build and TestFlight delivery follow a verified source snapshot. Browser fixture
screenshots and browser history tests only validate the synthetic React Native Web
environment; they do not validate UIKit/Android gestures, native navigation or device rendering.

## Mastra compatibility candidate

The dependency manifest remains `@mastra/core: ^1.58.0`; the lock candidate selects1.68.0,
the first stable release removing its exact MCPserver2.0.0 dependency. Memory1.26.1 and
pg1.20.0 stay unchanged and their peer ranges admit this version. The official release
preserves SDK-compatible tool context declarations:
https://github.com/mastra-ai/mastra/releases/tag/%40mastra/core%401.68.0

Cloud validation includes a bounded structural fake-model smoke for generate, stream,
tool execution and the fullStream events used by this API. Its fetch guard forbids network
requests. It does not validate external provider credentials or aborted Memory persistence.
Mastra1.62 changed cancellation transcript persistence: partial history may be saved on Stop.
A PostgreSQL-backed abort/history acceptance check is required before a server deployment.
This code-only mobile batch does not deploy the server.

Remaining dependency boundaries: braces and node-forge currently have no patched version;
Nodemailer requires10.0.6 (a major update from9.1.1). The audit gate remains enabled.
